# API Routes CODEMAP

> All endpoints prefixed with `/api/v1/`. Handlers validate input, call services, return responses. Uses `get_db` + `get_current_user` DI.

| File | Prefix | Key Endpoints |
|------|--------|---------------|
| `auth.py` | `/auth/` | `POST /sync-user`, `GET /oauth/{provider}/authorize`, `GET /oauth/{provider}/callback`, `GET /me`, `POST /logout` |
| `connections.py` | `/connections/` | `GET /`, `DELETE /{id}`, `POST /{id}/sync` (strava/komoot/wahoo/whoop/withings dispatch), `POST /whoop/backfill` |
| `activities.py` | `/activities/` | `GET /` (list+filter: sport_type, source, date range, q name search, distance/duration/tss ranges, sort_by/sort_order; `?include_context=true` attaches each cycling activity's cached §1.3 `ride_context` with zero extra queries; every item carries `has_streams` from id-only eager-loaded stream rows), `GET /summary` (aggregate totals: count, total distance/time/TSS across all matching activities), `GET /calendar`, `GET /{id}` (detail + streams + `has_streams`), `GET /{id}/streams`, `GET /{id}/context` (§1.3 — serves sync-time-precomputed ride metrics from `Activity.context` unless profile FTP moved; load context ATL/CTL/TSB computed on demand), `GET /{id}/analysis`, `GET/POST /{id}/ai-analysis`, `POST /backfill` (chunked SSE stream backfill), `POST /backfill-route-links`, `GET /merge-analysis`, `POST /import-gpx`, `POST /import-fit` |
| `lifting.py` | `/lifting/` | Sessions CRUD (`GET /sessions/active` = unfinished live-tracked session for `/lifting/live` resume; registered BEFORE `/{session_id}` so "active" isn't parsed as UUID), sets CRUD, PRs, volume trends, warmup templates, activity linking (`PUT /sessions/{id}/link`, `GET /sessions/{id}/linkable-activities`, `POST /backfill-links`), `GET /exercises` + `POST /exercises` + `PATCH/DELETE /exercises/{id}` (exercise library), `POST /prs/cleanup`, `GET /sessions/{id}/analysis`, `GET/POST /sessions/{id}/ai-analysis`, `POST /suggest-load` (%e1RM prescription, FL3). Session create accepts `started_at`, PATCH accepts `started_at`/`ended_at` (live flow) |
| `videos.py` | `/lifting/videos/` | **§1.1** strength-video API (R2 uploads only): `GET /` (list, filter by exercise_name), `POST /` (create uploaded video — requires `r2_key` + validated type/size), `GET /{id}`, `DELETE /{id}` (also deletes the R2 object, best-effort), `POST /upload-url` (R2 presigned PUT), `GET /{id}/stream-url` (R2 presigned GET). All upload endpoints 501 without R2 credentials. Backed by `LiftVideo` model + `047_create_lift_videos` / `048_drop_lift_video_url_columns` migrations |
| `routes.py` | `/routes/` | Route CRUD, filtering (incl. `surface_type`, `tag_ids`, `collection_id`, `is_favorite`, `min_quality_score`), GPX download/upload, sync, merge, duplicates + auto-merge. New: `/tags` (CRUD + assign/unassign), `/collections` (CRUD + smart from-filters), `/quality` (list + recompute), `/{id}/effort-estimate`, `/{id}/weather`, `/merged-view` (per-source polylines + ridden activity segments), `/heatmap/home` (activity points near home for heatmap), `/bulk/export-gpx`, `/bulk/delete`, `/duplicates/auto-merge` |
| `cycling/` | `/cycling/` | Profile (`GET/PATCH /profile`), FTP history (`GET/POST /ftp-history`, `POST /estimate-ftp`, `POST /backfill-ftp-history`, `POST /backfill-streams`), power (`GET /power-curve`, `/power-zones`, `/hr-zones`, `/power-vs-hr`, `/metrics-summary`, `/lifetime-pbs`, `/suggested-cycle`, `/power-model`, `/weather-analysis`), PRs (`GET/POST /prs`, `POST /prs/check`), training load (`GET /training-load`, `POST /recalculate-tss`), VO2max/decoupling (`GET /vo2max`, `/vo2max-history`, `/decoupling`, `/decoupling/{activity_id}`) |
| `cross_domain.py` | `/cross-domain` | Modal cross-domain insights — `GET ""` (list, optional `?insight_type=`), `GET /{insight_type}` |
| `charts.py` | `/charts/` | `GET /available`, `GET /{chart_name}` — registry-driven chart data; required params → 422, stream-heavy charts Redis-cached 5 min |
| `dashboard/` | `/dashboard/` | `GET /summary`, `GET /weekly-report`, `GET /today`, `GET /whoop-weekly`, `GET /monthly-summary`, `GET /streaks`, `GET /yearly-summary/{year}` |
| `webhooks.py` | `/webhooks/` | `GET /strava` (challenge), `POST /strava` (event receiver — HMAC-verifies + persists to `strava_webhook_events` queue for async Celery processing; never processes inline) |
| `export.py` | `/export/` | Data export endpoints: `GET /json` (§3.9 full portability export), `GET /lifting/csv`, `GET /activities/csv`, `GET /prs/csv`, `GET /activities/{id}/gpx`, PDF reports `GET /weekly-report/{week_start}`, `GET /monthly-report/{month}`, `GET /event-report/{event_id}` (§3.14 race-day prep PDF — 404 when event not found) |
| `training_plans.py` | `/training-plans/` | Thin router → `services/training_plan.py`. Plan CRUD, `POST /generate` (mixed-week template: rest Sun, strength Tue/Thu, cycle rides), `event_id` on POST/PATCH links event + auto-taper; PATCH days are non-destructive upsert by `day_date`; `GET /{plan_id}/week/{n}` (weekly view: Monday-aligned weeks, readiness CTL/ATL/TSB, weather + bad-weather badges, actual activity/lifting summaries, route matches on cycle days; `include_weather` query), `PATCH /{plan_id}/days/{day_id}` (targeted single-day partial update), `GET /{plan_id}/suggestions` (**§3.11** adaptive weekly advice via `services/adaptive.py` — TSB/recovery/conformity/health/deficiency → one-tap apply actions, 404 when plan not owned), FL2: `POST /{plan_id}/days/{day_id}/reschedule` (409 on occupied), `POST /{plan_id}/days/{day_id}/substitute` (422 on bad sport/type), `GET /{plan_id}/unplanned?days=N` (sessions on no plan day), `POST /{plan_id}/refresh-targets` (FL1 cycle FTP refresh + FL3 %e1RM strength refresh + CP/FTP mismatch) |
| `events.py` | `/events/` | Event CRUD with countdown/taper info, `upcoming_only` filter, `PUT/DELETE /{id}/result` (race retro → notifies `event_result`, deduped per event), `GET/POST /{id}/ai-analysis` |
| `workout_planner.py` | `/workout-planner/` | `GET /zones`, `POST /plan`, `POST /match-routes` — intensity zones, workout targets, route matching |
| `search.py` | `/search/` | Global ⌘P command-palette lookup — ILIKE across activities, routes, lifting sessions, exercises, goals, events; per-domain results with deep-link ids |
| `segments.py` | `/segments/` | **§3.13** ride climb segments — `GET ""` (list, optional `?route_id=`, PR-first), `GET /{segment_id}` (detail + leaderboard-of-self efforts sorted by elapsed). Route-scoped endpoints live in `routes.py`: `GET /{route_id}/segments`, `POST /{route_id}/segments/recompute` (detect climbs from route elevation profile + distance-align linked activity streams → efforts/PRs via `services/segments.py`) |
| `metrics.py` | `/metrics/` | Weight history (same-day dedup Withings > Whoop > Manual) + manual CRUD with optional body-composition fields (Withings/Whoop entries read-only); every write re-syncs the canonical profile reference weight (QW1), health analysis (`POST /health-alerts/analyze` — composite + regeneration signals, honors disabled/snoozed prefs for all types), `GET/PUT /health-preferences` (§3.12), `GET/POST /health-ai-analysis`, `GET /readiness` |
| `deficiency.py` | `/deficiency/` | `GET /` (`weeks` query, 4–26) — weakness analysis: strength standards, Big-3 ratios, push/pull balance, VO2max/FTP mismatch, decoupling, zone distribution |
| `nutrition.py` | `/nutrition/` | Ride fuel plans: `POST /fuel-plan` (generate from activity_id or planned_duration_min/planned_if), `GET/PATCH/DELETE /fuel-plan/{id}` (PATCH logs actuals), `GET /fuel-plan/activity/{activity_id}` — endpoint has error logging; actuals clearing (empty string → null) supported; regenerate/delete UI on frontend |
| `notifications.py` | `/notifications/` | In-app notifications: `GET /` (limit, unread_only), `PATCH /{id}/read`, `POST /read-all`, `GET/PATCH /preferences` (per-type toggles). Rows created by `services/notifications.notify()` from health alerts, PRs, goal milestones, plan reminders |
| `account.py` | `/account/` | §3.9 account deletion: `DELETE /delete` (body `{confirm_email}`; 422 if email mismatch; single SQL DELETE on `users` row — all children cascade via DB `ON DELETE CASCADE` FKs including encrypted OAuth tokens). Committed immediately; JWT becomes invalid after delete |
| `preferences.py` | `/user/preferences/` | §3.6 UI prefs: `GET /` (defaults merged: `unit_system=metric`, `locale=en-GB`, `time_format=24h`), `PATCH /` (partial, validated per-field, 422 on invalid). Stored in `User.preferences` JSONB via `services/preferences.py` |
| `push.py` | `/push/` | §3.8 Web Push: `GET /vapid-public-key` (404 when VAPID unset), `GET /subscriptions`, `POST /subscriptions` (upsert by endpoint), `DELETE /subscriptions` (body `{endpoint}`). Delivery + failure tracking/pruning in `services/push.send_push_to_user` (called from `notify()`) |
| `llm_analysis.py` | `/cycling/llm-analysis/` | `GET /latest` (id tie-break for same-second rows), `POST /on-demand`. `GET /history` removed (RM2 — no consumer) |
| `weather.py` | `/weather/` | Open-Meteo integration: `GET /current`, `GET /forecast` (days 1–7), `GET /historical` (start/end dates), `POST /tag-activity/{id}`, `GET /for-activity/{id}` — lat/lng optional (falls back to user home location); provider failures → 503 |
| `goals.py` | `/goals/` | Semantic goals (Phase 6) — thin router over `services/goals.py` + `services/goal_metrics.py`. `GET /` (`status_filter`, items enriched with direction/alignment_pct/progress_pct/metric label+unit), `POST /` (validates metric in registry + required filters, snapshots `starting_value`), `GET /metrics` (registry listing for dynamic forms), `GET/PATCH/DELETE /{id}`, `POST/GET /{id}/checkins`, `POST /{id}/reactivate`. Status transitions run on every read/write path via `update_goal_status` |
| `projections.py` | `/projections/` | Phase 7 — projections & success prediction. `GET /goal/{goal_id}` (trend, projected date, badge, history, projection_line), `GET /metric/{metric_key}?months=6&filter_json={}` (trend for any registry metric), `GET /tsb/{plan_id}?days=14` (event-linked TSB trajectory only; 400 if no event linked) |
