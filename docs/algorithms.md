## Training Load Formulas

- **TSS**: `(duration_s × NP × IF) / (FTP × 3600) × 100`, `IF = NP / FTP`. NP = 30s rolling avg → 4th-power mean → 4th root ([`tss.py`](../backend/app/services/cycling/tss.py) `compute_normalized_power()`; needs ≥30 samples, drops null/≤0). hrTSS fallback via %HRR (`auto_compute_hr_tss_for_activity()` — needs profile LTHR + resting HR ≤30 d old). Auto-computed during sync from `normalized_power ?? average_power` when FTP exists, else hrTSS, else None.
- **CTL/ATL/TSB**: Computed on-the-fly. Canonical path ([`training_load.py`](../backend/app/services/cycling/training_load.py) `compute_training_load()`): `CTL_t = CTL + (TSS − CTL) × (1 − e^(−1/42))`, ATL with τ=7, `TSB = CTL − ATL`, 90-day lookback, non-finite TSS → 0. ⚠️ `projections.tsb_projection()` uses the simplified `/42` and `/7` divisors instead — run-2 audit quantified the error at <1 CTL point over 14 d (cosmetic, left as-is). `tsb_projection()` also emits per-day ±20%-adherence sensitivity bands (`tsb_low`/`tsb_high`).
- **VAM**: `elevation_gain_m / duration_h`. **VI** = NP/AP (lower = steadier).
- **Lifting load** ([`lifting.py`](../backend/app/services/lifting.py) `estimate_lifting_tss()`): Foster session load — `(tonnage_kg / bodyweight_kg) × (session_RPE / 10) × 1.4`, where tonnage is `Σ(weight_kg × reps)` over **non-warmup** sets and `session_RPE` is the mean of working-set RPEs (falling back to `rpe_session`, then 6.0). Dividing by bodyweight makes it a *volume load* (kg lifted per kg bodyweight), so a 60 kg and a 120 kg lifter doing the same tonnage are not scored the same. `LIFT_TSS_PER_VOLUME_LOAD = 1.4` is a display-scale constant, not a physiological claim; it preserves the old anchor of ~60 TSS for a 1-hour session at RPE 7 (a bodyweight-normalised hour of moderate lifting is ~60 volume load → `60 × 0.7 × 1.4 ≈ 59`). Bodyweight is the most recent `WeightLog` (`latest_body_weight()`); **without a weigh-in it falls back** to the older `duration_min × avg_RPE / 7` estimate, which is blind to weight and reps. Recomputed weekly with `force=True` by `aggregate_video_analyses_weekly`, because both inputs (sets, bodyweight) change after the fact.

- **Power profile norms**: static Coggan-style W/kg percentile table ([`power_profile.py`](../backend/app/services/cycling/power_profile.py): 5s/60s/5min/20min/60min × p25/50/75/90, trained-male-rider norms, not age/sex-adjusted) with log-linear interpolation across durations (fraction over ln(duration)); used by `power_duration_percentile`.
- **Ramp rate**: weekly ΔCTL with safe bands — optimal build +3 to +8 CTL/wk, >8 flagged as risky ramp.

## Specialised Algorithms

- **VO2max** ([`vo2max.py`](../backend/app/services/cycling/vo2max.py)): FRIEND-ergometry `_friend_vo2max() = (10.649 × W)/kg + 3.5` (from Nes et al. 2018, PMID 29692203; >4× lower error than the traditional ACSM 11.016×W/kg+7). Signals: 5-min best power (conf 0.7 with weight, 0.4 with 75kg default), 8-min best scaled to its 5-min equivalent via Riegel (conf 0.5, weight required; live via the 480s power-curve bucket — FRIEND is calibrated on maximal ~5-min power, so the raw 8-min read is never fed directly), Uth HR `15.3 × HRmax/HRrest` (conf 0.6; resting HR must be ≤30 d old). Selection = highest confidence, tie-break by value. Sanity gate 20–90 ml/kg/min. History flags `weight_defaulted`. Classes: Poor <35 / Below Avg <45 / Average <55 / Good <65 / Excellent <75 / Superior 75+ (general-population bands, not age/sex-adjusted). Endpoint: `GET /api/v1/cycling/vo2max`.
- **Decoupling** ([`vo2max.py`](../backend/app/services/cycling/vo2max.py) `compute_decoupling_from_streams()`): ratio of half-means (mean power / mean HR per half — TrainingPeaks convention, not the mean of per-sample ratios), `% = (r1 − r2)/r1 × 100`. Needs ≥60 valid (power>0, HR>0) pairs. Classes: <5 Excellent / ≤8 Acceptable / >8 Aerobic Deficiency. History gate: rides ≥60 min with power+HR streams (`compute_decoupling_history`, default 60 min); single-activity path has no duration gate.
- **Power zones**: 7 Coggan power zones %FTP (Z1 0–55 … Z7 150+), 6 HR zones %LTHR, 5 LTHR-HR zones ([`zones.py`](../backend/app/services/cycling/zones.py)). Zone distribution uses stream `resolution` weighting, drops non-finite/≤0 samples.
- **FTP estimation** ([`power_curve.py`](../backend/app/services/cycling/power_curve.py)): tiers 60-min direct (0.9) / 20-min ×0.95 gold (1.0) / 30-min ×0.97 (0.9; log-duration interpolation between the anchored 20-min/60-min points) / 8-min ×0.90 (0.85; Allen/Coggan protocol factor) / 5-min ×0.85 (0.5) + Riegel `P2 = P1×(D1/D2)^0.06` extras incl. 10-min (0.6/0.4/0.3; the invented 10-min ×0.92 factor tier was removed), gated to within 0.3 of best confidence, confidence-weighted mean, clamp 50–600W. Buckets 5s–120min (incl. 8min); shared `best_power_rolling_average()` prefix-sum helper for read + backfill. Write paths clamp 50–600W (422 outside).
- **Workout Planner** ([`workout_planner.py`](../backend/app/services/workout_planner.py)): 5 planner zones z1–z5 by IF (0–0.55 … 1.05–1.20) + LTHR% bands — distinct from the 7 Coggan power zones above. Readiness by TSB: >25 z5 very fresh / >5 z5 fresh / >−10 z3 neutral / >−30 z2 fatigued / else z1. A *sustained* TSB >25 with falling CTL is detraining, not form (the planner copy carries this caveat via `compute_workout_zones`). Route match weights TSS 35% / duration 25% / power 25% / HR 15%, renormalized over present signals; unridden-route penalty ×0.85, confidence 0.3. Unridden TSS estimate: IF 0.70 base (+≤0.15 elevation adj), 25 km/h duration fallback. Endpoints: `GET /api/v1/workout-planner/zones`, `POST /plan`, `POST /match-routes`.
 - **Ride fuel** ([`nutrition.py`](../backend/app/services/nutrition.py)): in-ride carbs capped at 90 g/h (`MAX_CARBS_PER_HOUR`); anything above needs fructose:glucose ≈1:2 substrates + gut training (`carb_fuel_note()` surfaced as `fuel_note`).
- **Deficiency** ([`deficiency.py`](../backend/app/services/deficiency.py)): Big-3 standards Squat 1.0/1.5/2.0/2.5×BW, Bench 0.6/1.0/1.4/1.8×BW, Deadlift 1.2/1.75/2.4/3.0×BW; ratios bench:squat ideal 0.65–0.75 (flags <0.55 critical, <0.65 medium, >0.85 high), dead:squat 1.0–1.35, bench:dead 0.45–0.75; push:pull ideal 1.0–1.3 (flags <0.7 high, <1.0 medium, ≤1.6 low, above medium); zone flags >80% Z1/Z2 = missing intensity, >40% Z4+ = too much, <5% Z3 = missing tempo; VO2↔FTP rank-mismatch + decoupling avg over ≥3 long rides.
- **Projections** ([`projections.py`](../backend/app/services/projections.py)): OLS on day-offsets, 12-week window, badges need ≥4 points (else "Not enough data"): On Track (proj ≤ target) / At Risk (≤ target+30d) / Unlikely (wrong direction or beyond); already-met target projects today (On Track). Metric trends for the 1RM family (estimated_1rm, BW ratios, big3_total) are rebuilt from per-session best sets (PR rows are in-place). TSB projection event-linked only (`race_day_tsb` = entry at the event date when inside the window); freshness >5 optimal / ≥−5 neutral / ≥−10 slightly fatigued / else fatigued.
- **Adaptive** ([`adaptive.py`](../backend/app/services/adaptive.py) §3.11): pure inference `derive_adaptive_advice()` — TSB ≤−20 cut / ≥+5 raise, recovery <40 rest, conformity <70 ease / ≥90 + non-declining build (single cut vote dominates), health alerts gate everything, cut ×0.85 / raise ×1.08 on next ≤3 training days (cycle power/duration/TSS 60–600/30–600/10–400 clamps; strength volume/RPE clamps; alert severity ranked worst-first). 15 unit tests in `tests/test_adaptive.py`.
- **Segments** ([`segments.py`](../backend/app/services/segments.py) §3.13): climbs ≥30m gain at ≥3% avg over ≥150m (HC/1–4 `climb_category`), effort via velocity×resolution distance alignment (≥90% coverage, 25m + 5% tolerance), VAM/speed/power/HR per window.
- **Health analysis** ([`health_analysis.py`](../backend/app/services/health_analysis.py)): composites — overtraining TSB 40% + recovery 35% + HRV 15% + sleep 10%; injury volume-spike (EWMA 4-wk time constant, needs ≥2 active priors; +20/30/50% bands) 55% + rest-days (4/5-6/7+ consecutive) 45%; illness recovery 25% + RR 20% + HRV 25% + sleep 15% + unexplained-fatigue 15% (RR missing → redistribute /0.80). Severity ≥85 critical / ≥65 warning / ≥45 info. Regen defaults (§3.12): FTP drop 8%/15%, sleep σ 60/120 min, RHR +5/+8 bpm vs 30-day baseline; per-user overrides in `User.health_preferences`.
- **Lift-video analysis (§3.18)** ([`pose_analysis.py`](../backend/app/integrations/pose_analysis.py)): MediaPipe PoseLandmarker (heavy, CPU, 10 fps) → 2D + **metric 3D world landmarks**. Rep detection from the median-filtered knee-angle signal (auto path drops cycles <75% of max ROM; declared path keeps the best consecutive run). **Bar velocity** is metric: world landmarks are hip-centred (global translation removed), so squat/deadlift use the change in **hip→ankle distance** (leg extension) and presses/bench/stone track wrist y. **Form rules are view-gated** — sagittal measures (torso lean, hip-vs-knee depth, hip-extension lockout, back rounding) only run when the camera view is `side`; low-bar squats read ~147° hip extension standing, so non-side lockout uses the knee only. Form score = mean of per-rep scores (not summed). RPE from velocity loss across a multi-rep set only (recalibrated bands, `None` for single reps). The video RPE heuristic uses the standard RPE↔RIR mapping (`RIR = 10 − RPE`); `POST /suggest-load` returns `safety_warning` at ≥95% of 1RM. Camera view is user-declared (`lift_videos.camera_view`); a Gemini single-frame classifier exists but is gated off (`VIDEO_VIEW_VLM_ENABLED`) due to the small daily quota. Overlay video (skeleton + bar path) rendered by `render_overlay_video()`. Eval harness: `scripts/video_eval.py`.
- **VBT load–velocity (§3.18)** ([`vbt.py`](../backend/app/services/vbt.py)): fits `velocity = slope·load + intercept` (least squares) over the user's analysed sets that have both `weight_kg` and `mean_concentric_velocity`; **estimated 1RM** = load where the line crosses the minimal velocity threshold (Squat 0.30, Bench/Deadlift 0.15, Press 0.20 m/s; default 0.20). Confidence from point count / distinct loads / R²; 1RM suppressed for a non-negative slope or an extrapolation beyond 0.5–2.5× the observed max load. Endpoint `GET /api/v1/lifting/videos/vbt/profile`.
- **Encryption**: OAuth tokens encrypted at rest via Fernet ([`encryption.py`](../backend/app/services/encryption.py)). `EncryptedString` TypeDecorator transparent to services.
- **Modal intelligence workers** (`backend/app/integrations/`, pure-compute, stdlib-only at module scope): **power models** — Morton 3-param `P(t) = W'/(t+k) + CP` with `k = W'/(Pmax−CP)` via hand-rolled Levenberg-Marquardt (CP 50–600W, W' 1–100kJ, Pmax CP+50–2500W, needs ≥4 duration buckets); personalized VO2max = FRIEND `10.649 × W/kg + 3.5` on best ~5-min power read from the power-duration curve (exact 300s bucket, else log-linear interpolation between bracketing buckets, never extrapolation; same maximal input as `estimate_vo2max`), gated to 20–90; without a readable 300s the legacy power–HR regression at LTHR (else 170 bpm fallback) applies only when R² ≥ 0.5 (`weak_regression_gated` otherwise); method/R²/points/HR-anchor/maximal-watts persist on `cycling_profiles` (migration 098); adaptive CTL/ATL taus = grid search (CTL 21–63 step 3, ATL 3–14) maximizing TSB–HRV correlation, canonical 42/7 defaults on insufficient data. Fitted taus persist only with ≥45 samples and R² ≥ 0.10 (`ADAPTIVE_TAU_MIN_N`/`ADAPTIVE_TAU_MIN_R2`; `weak_fit_gated` otherwise, and `training_load_for_user(include_meta=True)` surfaces the taint). FTP/VO2max estimates carry cross-method 95% intervals (`blend_ci_95` in `power_curve.py` → `ci_low`/`ci_high` on both responses). **Terrain** — climb runs ≥3% over ≥150m with ≥30m gain (mirrors §3.13 `detect_climb_segments`); climb categories mirror `segments.climb_category` gain+gradient bands; typing uses climb-rate `total_climb/span` (signed-mean gradients cancel on loops) with flat <1.0%, rolling `rolling_index > 0.8` (≤2 climbs), mountainous ≥2 climbs + >500m, hilly >200m, else mixed. **Map-matching** — OSM PBF two-pass parse (no global location index; node coords come from PBF records), edge u/v are real OSM node ids so the `_shares_node` continuity filter fires across ways; radii 40/60m. **Segments** — DBSCAN (eps 0.4, min_samples 2) over gradient/length/gain shape features; sustainedness = `gain/(length × grad/100)`. **Weather** — OLS power/HR/decoupling vs temp, headwind buckets assume Open-Meteo FROM-convention wind direction; insights gated on R² ≥ 0.1 + sample minima. **Cross-domain** — sleep→next-day power pairing, lagged HRV–power cross-correlation (±7d), taper −20%, race verdict ±3%. Combined-load sums (`TSS + volume_kg/10`) are exploratory/insights-only and never feed `/today` — the action path keeps sports separate via CD1 legs/cycling flags.
