## Training Load Formulas

- **TSS**: `(duration_s × NP × IF) / (FTP × 3600) × 100`, `IF = NP / FTP`. NP = 30s rolling avg → 4th-power mean → 4th root ([`tss.py`](../backend/app/services/cycling/tss.py) `compute_normalized_power()`; needs ≥30 samples, drops null/≤0). hrTSS fallback via %HRR (`auto_compute_hr_tss_for_activity()` — needs profile LTHR + resting HR ≤30 d old). Auto-computed during sync from `normalized_power ?? average_power` when FTP exists, else hrTSS, else None.
- **CTL/ATL/TSB**: Computed on-the-fly. Canonical path ([`training_load.py`](../backend/app/services/cycling/training_load.py) `compute_training_load()`): `CTL_t = CTL + (TSS − CTL) × (1 − e^(−1/42))`, ATL with τ=7, `TSB = CTL − ATL`, 90-day lookback, non-finite TSS → 0. ⚠️ `projections.tsb_projection()` uses the simplified `/42` and `/7` divisors instead — run-2 audit quantified the error at <1 CTL point over 14 d (cosmetic, left as-is).
- **VAM**: `elevation_gain_m / duration_h`. **VI** = NP/AP (lower = steadier).

## Chart System

Backend registry [`CHART_REGISTRY`](../backend/app/api/charts.py) → [`ChartService`](../backend/app/services/charts.py) → frontend [`Chart`](../frontend/src/components/charts/Chart.tsx) renders Recharts (line, bar, scatter, area, pie + custom CSS-grid heatmap). 32 charts registered: weekly_tss, estimated_1rm_history, weekly_volume, sleep_quality_trend, whoop_strain_trend, training_load, ftp_history, stream_power_curve, power_zones, hr_zone_distribution, daily_tss, exercise_progress, power_curve_comparison, strain_vs_recovery, recovery_vs_performance, hrv_trend_detailed, weight_trend, body_composition_trend, training_load_balance, rest_day_analysis, vo2max_trend, decoupling_trend, resting_hr_trend, respiration_trend, whoop_recovery_trend, periodization, ramp_rate, wkg_power_curve, power_duration_percentile, consistency_heatmap, sleep_consistency, strength_balance. Reference areas supported for zone coloring (per-axis via `y_axis`). Series may target a secondary Y axis (`y_axis: "right"`). Required registry params return 422 when missing; stream-heavy charts are Redis-cached for 5 min.

- **Power profile norms**: static Coggan-style W/kg percentile table ([`power_profile.py`](../backend/app/services/cycling/power_profile.py): 5s/60s/5min/20min/60min × p25/50/75/90, male-rider approx) with linear interpolation across durations; used by `power_duration_percentile`.
- **Ramp rate**: weekly ΔCTL with safe bands — optimal build +3 to +8 CTL/wk, >8 flagged as risky ramp.

## Specialised Algorithms

- **VO2max** ([`vo2max.py`](../backend/app/services/cycling/vo2max.py)): ACSM `_acsm_vo2max() = (11.016 × W)/kg + 7` (1.8 × 6.12 kgm/min per W). Signals: 5-min best power (conf 0.7 with weight, 0.4 with 75kg default), 8-min best (conf 0.6, weight required; live via the 480s power-curve bucket), Uth HR `15.3 × HRmax/HRrest` (conf 0.6; resting HR must be ≤30 d old). Selection = highest confidence, tie-break by value. Sanity gate 20–90 ml/kg/min. History flags `weight_defaulted`. Classes: Poor <35 / Below Avg <45 / Average <55 / Good <65 / Excellent <75 / Superior 75+. Endpoint: `GET /api/v1/cycling/vo2max`.
- **Decoupling** ([`vo2max.py`](../backend/app/services/cycling/vo2max.py) `compute_decoupling_from_streams()`): mean per-sample power:HR ratio per half, `% = (r1 − r2)/r1 × 100`. Needs ≥60 valid (power>0, HR>0) pairs. Classes: <5 Excellent / ≤8 Acceptable / >8 Aerobic Deficiency. History gate: rides ≥60 min with power+HR streams (`compute_decoupling_history`, default 60 min); single-activity path has no duration gate.
- **Power zones**: 7 Coggan power zones %FTP (Z1 0–55 … Z7 150+), 6 HR zones %LTHR, 5 LTHR-HR zones ([`zones.py`](../backend/app/services/cycling/zones.py)). Zone distribution uses stream `resolution` weighting, drops non-finite/≤0 samples.
- **FTP estimation** ([`power_curve.py`](../backend/app/services/cycling/power_curve.py)): tiers 60-min direct (0.9) / 20-min ×0.95 gold (1.0) / 30-min ×0.95 (0.95) / 8-min ×0.90×0.95 (0.85) / 10-min ×0.92×0.95 (0.7) / 5-min ×0.85 (0.5) + Riegel `P2 = P1×(D1/D2)^0.06` extras (0.6/0.4/0.3), gated to within 0.3 of best confidence, confidence-weighted mean, clamp 50–600W. Buckets 5s–120min (incl. 8min); shared `best_power_rolling_average()` prefix-sum helper for read + backfill. Write paths clamp 50–600W (422 outside).
- **Workout Planner** ([`workout_planner.py`](../backend/app/services/workout_planner.py)): 5 planner zones z1–z5 by IF (0–0.55 … 1.05–1.20) + LTHR% bands — distinct from the 7 Coggan power zones above. Readiness by TSB: >25 z5 very fresh / >5 z5 fresh / >−10 z3 neutral / >−30 z2 fatigued / else z1. Route match weights TSS 35% / duration 25% / power 25% / HR 15%, renormalized over present signals; unridden-route penalty ×0.85, confidence 0.3. Unridden TSS estimate: IF 0.70 base (+≤0.15 elevation adj), 25 km/h duration fallback. Endpoints: `GET /api/v1/workout-planner/zones`, `POST /plan`, `POST /match-routes`.
- **Deficiency** ([`deficiency.py`](../backend/app/services/deficiency.py)): Big-3 standards Squat 1.0/1.5/2.0/2.5×BW, Bench 0.6/1.0/1.4/1.8×BW, Deadlift 1.2/1.75/2.4/3.0×BW; ratios bench:squat ideal 0.65–0.75 (flags <0.55 critical, <0.65 medium, >0.85 high), dead:squat 1.0–1.35, bench:dead 0.45–0.75; push:pull ideal 1.0–1.3 (flags <0.7 high, <1.0 medium, ≤1.6 low, above medium); zone flags >80% Z1/Z2 = missing intensity, >40% Z4+ = too much, <5% Z3 = missing tempo; VO2↔FTP rank-mismatch + decoupling avg over ≥3 long rides.
- **Projections** ([`projections.py`](../backend/app/services/projections.py)): OLS on day-offsets, 12-week window, badges need ≥4 points (else "Not enough data"): On Track (proj ≤ target) / At Risk (≤ target+30d) / Unlikely (wrong direction or beyond); already-met target projects today (On Track). Metric trends for the 1RM family (estimated_1rm, BW ratios, big3_total) are rebuilt from per-session best sets (PR rows are in-place). TSB projection event-linked only (`race_day_tsb` = entry at the event date when inside the window); freshness >5 optimal / ≥−5 neutral / ≥−10 slightly fatigued / else fatigued.
- **Adaptive** ([`adaptive.py`](../backend/app/services/adaptive.py) §3.11): pure inference `derive_adaptive_advice()` — TSB ≤−20 cut / ≥+5 raise, recovery <40 rest, conformity <70 ease / ≥90 + non-declining build (single cut vote dominates), health alerts gate everything, cut ×0.85 / raise ×1.08 on next ≤3 training days (cycle power/duration/TSS 60–600/30–600/10–400 clamps; strength volume/RPE clamps; alert severity ranked worst-first). 15 unit tests in `tests/test_adaptive.py`.
- **Segments** ([`segments.py`](../backend/app/services/segments.py) §3.13): climbs ≥30m gain at ≥3% avg over ≥150m (HC/1–4 `climb_category`), effort via velocity×resolution distance alignment (≥90% coverage, 25m + 5% tolerance), VAM/speed/power/HR per window.
- **Health analysis** ([`health_analysis.py`](../backend/app/services/health_analysis.py)): composites — overtraining TSB 40% + recovery 35% + HRV 15% + sleep 10%; injury volume-spike (EWMA 4-wk time constant, needs ≥2 active priors; +20/30/50% bands) 55% + rest-days (4/5-6/7+ consecutive) 45%; illness recovery 25% + RR 20% + HRV 25% + sleep 15% + unexplained-fatigue 15% (RR missing → redistribute /0.80). Severity ≥85 critical / ≥65 warning / ≥45 info. Regen defaults (§3.12): FTP drop 8%/15%, sleep σ 60/120 min, RHR +5/+8 bpm vs 30-day baseline; per-user overrides in `User.health_preferences`.
- **Lift-video analysis (§3.18)** ([`pose_analysis.py`](../backend/app/integrations/pose_analysis.py)): MediaPipe PoseLandmarker (heavy, CPU, 10 fps) → 2D + **metric 3D world landmarks**. Rep detection from the median-filtered knee-angle signal (auto path drops cycles <75% of max ROM; declared path keeps the best consecutive run). **Bar velocity** is metric: world landmarks are hip-centred (global translation removed), so squat/deadlift use the change in **hip→ankle distance** (leg extension) and presses/bench/stone track wrist y. **Form rules are view-gated** — sagittal measures (torso lean, hip-vs-knee depth, hip-extension lockout, back rounding) only run when the camera view is `side`; low-bar squats read ~147° hip extension standing, so non-side lockout uses the knee only. Form score = mean of per-rep scores (not summed). RPE from velocity loss across a multi-rep set only (recalibrated bands, `None` for single reps). Camera view is user-declared (`lift_videos.camera_view`); a Gemini single-frame classifier exists but is gated off (`VIDEO_VIEW_VLM_ENABLED`) due to the small daily quota. Overlay video (skeleton + bar path) rendered by `render_overlay_video()`. Eval harness: `scripts/video_eval.py`.
- **VBT load–velocity (§3.18)** ([`vbt.py`](../backend/app/services/vbt.py)): fits `velocity = slope·load + intercept` (least squares) over the user's analysed sets that have both `weight_kg` and `mean_concentric_velocity`; **estimated 1RM** = load where the line crosses the minimal velocity threshold (Squat 0.30, Bench/Deadlift 0.15, Press 0.20 m/s; default 0.20). Confidence from point count / distinct loads / R²; 1RM suppressed for a non-negative slope or an extrapolation beyond 0.5–2.5× the observed max load. Endpoint `GET /api/v1/lifting/videos/vbt/profile`.
- **Encryption**: OAuth tokens encrypted at rest via Fernet ([`encryption.py`](../backend/app/services/encryption.py)). `EncryptedString` TypeDecorator transparent to services.
