# DSH steering & documentation audit — 2026-11-06

**Goal**: optimise FitTrack for DeepSeek Harness. The governing constraint is
that DSH injects `AGENTS.md` into **every** session, while docs and skills are
loaded on demand. The audit therefore optimised for (1) context economy, (2)
instructions that DSH can actually follow, and (3) claims that do not rot.

## Scope and method

- **Structural pass over all documentation**: 265 Markdown files scanned for
  relative links, cross-file references, and OpenCode-only instructions.
- **Full read** of the always-injected and routed steering docs: `AGENTS.md`,
  `docs/RUNNING.md`, `docs/OPENCODE.md`, `README.md`, `.dsh/README.md`, the
  eight project skills, and the six CODEMAPs.
- **Fact checks against code** where a doc made a countable or checkable claim:
  migration head (119), table count (57), graph files, skill frontmatter, and
  the migration-head guard.
- **Not** a line-by-line correctness review of every plan's status or every
  algorithm description; those are called out as follow-ups where the staleness
  was visible.

   (e.g. `cycling-page-production.md` says HELD and "78 commits behind";
   `routes-atlas-2026-11-05.md` says "not merged"). Add a one-line `Status:` to
   each, or archive finished ones. `plans/README.md` is the place to start.

   `opencode.json`, `tui.json`, `.opencode/`, and `docs/OPENCODE.md`, and drop
   the DSH↔OpenCode skill-coverage test. Keeping both doubles the skill surface.
3. **Fix historical pitfall citations**: ~15 plan/CODEMAP references use stale
   numbers. Prefer citing the title (`docs/PITFALLS.md` → "bilateral weights")
   over a number, or re-check each against the canonical list.
4. **Guard the table count** if it is kept in `AGENTS.md`; otherwise remove it
   (the models CODEMAP is the authority).
5. **Clean root clutter**: `Continue` (0 B), `prompt.txt`, `RMI-08-...md`;
   decide whether `frontend/public/tmp/` is gitignored or deleted.
6. **Reconcile `docs/BUGS.md` counts** and verify the README wiki metric count.
